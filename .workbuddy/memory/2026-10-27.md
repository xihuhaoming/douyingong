### 结论：控制遮罩宽度做推拉 —— 可以，但必须「宽度 + 位置一起改」
只改宽度（锚点 0.5 对称缩放）会让一侧立刻露黑边。正确做法是**外侧那条边钉死**：
- 左遮罩：左缘钉死 `LM_EDGE`，右缘 = 交界 b → `w = b - LM_EDGE`，`center = LM_EDGE + w/2`

## 16:10 行程改自动计算（同向同步）+ 真机验证通过

### 用户最终定的方向
两张图**同向、同量**平移（不是反向）：value>0 → 两图一起往右；value<0 → 一起往左。

### 实现（assets/script/TugOfWar.ts）
- `computeRange()`：上限 = 「每张图必须盖住自己遮罩窗口」反推。
  窗口 = 屏幕可见 ∩ 自己遮罩 − 中线挡住的部分。算出 `rangeRight ≥ 0` / `rangeLeft ≤ 0`。
- 新增 `chainX()` / `spanX()`：**沿父链一路加到根**（不要停在名为 Canvas 的节点上）。
- `update()`：`d = value>=0 ? value*rangeRight : -value*rangeLeft`，两图各 `base + d`。
- 场景里有场景按钮时不再自建按钮（`!this.pick('ButtonLeft')` 才建），HUD 照建。
- HUD 第三行实时显示行程。

### 踩到的坑（重要）
**CenterLine 挂在 UICanvas 下，和主 Canvas 是兄弟节点。**
`chainX` 若在 `name === 'Canvas'` 处停，中线会算出场景坐标 373.9、
背景算出 Canvas 局部 -295.7，两套坐标系混用 → 行程全错。
必须一路加到 `parent === null`，全部用场景根坐标；可见范围用 `chainX(Canvas) ± visibleW/2`。

## 18:28 顶部数值绑定 + 角色动画正/倒放

### 需求
点「增加左侧/右侧」时：
1. 顶部「人间道 / 魔道」两个数值要跟着变
2. 动画按推力方向正放/倒放：加左侧 → 左侧往前（推）、右侧往后（后仰）；加右侧反之

### 关键发现
- **AnimationState 有公开的 `setTime(time)` 和 `sample()`**（在 cc.d.ts 里确认）。
  所以不用赌 `speed` 的正负，直接接管时间轴：`st.speed = 0` → 每帧 `setTime(t)` + `sample()`。
  进度变大 = 往前播，变小 = 往后播，语义干净。
- 两个角色各只有一条 Attack 序列帧 clip（spriteFrame 轨道）：
  - LeftPeopleAttack：28 帧，state.length = 0.4667s
  - RightPeopleAttack：17 帧，state.length = 0.2833s
- 顶部结构：`UICanvas/TopUITool/{LeftPeople,RightPeople}`，各自下面有
  `ScoreBg/Score`(Label) 和 `ProgressBar`（左侧 reverse=false、右侧 reverse=true，都 progress=1）。
  **两个 Score 重名，必须按子树找**（`pickIn(root, name)`），不能全局 pick。
- 中间是 VS 徽章，两条力量条不是拼成一条 → `bindTopProgress` 默认 **false**，怕一开两款条同时缩水很怪。

### 映射（已验证）
```
pL = 0.5 - value * animGain * 0.5      // 左角色：value<0（左优）→ pL 变大 = 往前推
pR = 0.5 + value * animGain * 0.5      // 右角色：反之
time = p * state.length
```
animGain 默认 1（推力差走满 [-1,1] 正好播完一遍）；调大更夸张但会到顶停住。

## 21:42 改成「角力四通道」：帧号不再累加，改成 tug 镜像映射

### 先说结论（这是回复用户"要不要倒放"的核心）
**整条 clip 不能倒放。** 实测两个 clip（`assets/bundle/anim/*.anim` 都是 `cc.animation.ObjectTrack` +
`cc.animation.TrackPath` → `spriteFrame` 的**序列帧**）：
- `LeftPeopleAttack`：28 帧 @60fps，`_duration=0.4667`，**首帧≠末帧**
- `RightPeopleAttack`：17 帧 @60fps，`_duration=0.2833`，**首帧≠末帧**
判断标准就一条：**首帧 == 末帧（闭环）才能双向 scrub**；否则是"起手→出招→收招"的单向动作，
倒放 = 收招变起手，观感是倒带录像。
**正确做法**：砍掉尾部「收招」段，只留「松→紧」的连续姿态区间，在这段里双向滑动 →
往回走 = 被顶回，语义成立。这就是 `usableRatio = 0.78` 的来历（左用 0~21 帧、右用 0~12 帧）。

### 拉锯感 = 四个并行通道，帧序只占其一
① 背景/绳标平移（已有）② 身体倾角（新增）③ 使劲循环（新增，时间驱动）④ 点按顿帧（新增）
只做 ① 的话，无论帧序怎么排都不像角力。

  `nodeL/R`、`baseScaleL/R`、`baseAngleL/R`。
- **核心新方法** `syncActorPose(dt)`（在 `update` 里每帧调）：
  ```
  fu = (1 - tug) / 2                     // 左方用力程度
  左帧 = fu * 左可用帧数                  // 镜像映射
  右帧 = (1 - fu) * 右可用帧数

frameL = spanL * loseFrameRatio * (1 - wl)  // 左数值高 → wl→1 → 左帧→0
frameR = spanR * loseFrameRatio * wl        // 右数值高 → wl→0 → 右帧→0
```

  如果抬腿帧不在正中，直接调这个值（0.4 / 0.6）即可。
- 抖动改成**同相位、只往前顶**：`j = amp * (0.5 + 0.5*sin)`，范围 0~amp。
  之前是 `sin*j`（正负都有），占优方贴在 0 帧会被 clamp 成 0 → 看着像卡死；

## 22:22 改成 Push↔Hit 串成闭环（不再单支 Loop）

- 新属性 `turnThreshold = 0.02`：优势翻转死区（满分×2%）。分差小于它不翻转锚点。
